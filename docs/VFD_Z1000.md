# Yaskawa Z1000 drive simulator

The Yaskawa Z1000 HVAC drive, behind the simulator's drive interface
(`hvacsim/models/components/drives/z1000.py`). Anywhere the simulator uses a
drive, it can be a Z1000:
- the standalone fan (`vfd_fan`);
- the AHU fan array;
- the chilled and hot water plant pumps;
- the cooling tower fans.

The design is in [DRIVE_INTERFACE_DESIGN.md](DRIVE_INTERFACE_DESIGN.md).

**Source documents:**
- Yaskawa *Z1000 Programming Manual* SIEP YAIZ1U 03C:
  - chapter 1: parameter details;
  - B.7: BACnet objects.
- Yaskawa *Z1000 User Manual* TOEP C710616 45H:
  - 3.9: control terminals;
  - 5.3: faults and alarms.

Values not from the manuals are marked *(A)*.

## Choosing the Z1000

| Where | How |
|---|---|
| Standalone drive | `templates/vfd_z1000_hardwired.yaml` (SF-3-VFD) or `templates/vfd_z1000_bacnet.yaml` (SF-4-VFD) |
| AHU fan array | `equipment.params.fan_drive_model: z1000` |
| Plant pumps / tower fans | `drive_model` column in the CSV row: `z1000` |

**Plant parameter overrides** (`pchwp_drive`, `ct_fan_drive`, …) use the
drive's own parameter names. With mixed drives in one group, give them per
model:

```yaml
pchwp_drive: { z1000: { c1_01: 45.0 }, ach580: { accel_time_1: 45.0 } }
```

**ALC points don't change.** `pchwp1_ss`, `_vfd_spd`, `_amps`, `_vfd_fb` and
`_vfd_flt` mean the same thing whichever drive is installed. Only the
terminals behind them differ:

| ALC point | ACH580 | Z1000 |
|---|---|---|
| start BO | DI1 | S1 (H1-01 = 40) |
| speed AO 0-10 V | AI1 | A1 (H3-01 = 0) |
| safety chain | DI4 (20.41) | S3 (H1-03 = B1 Customer Safeties) |
| status BI | RO2 | M1-M2 (H2-01 = 0 During Run) |
| fault BI, closed = healthy | RO3 (Fault (-1)) | MB-MC (fault relay N.C.) |
| speed feedback AI | AO1 | FM (H4-01 = 102) |

## Terminals: HVAC Initialization layout (A1-03 = 3410)

| Terminal | Setting | Function |
|---|---|---|
| S1 | H1-01 = 40 | Forward run (2-wire) |
| S2 | H1-02 = 41 | Reverse run (not simulated: a fan runs forward) |
| S3 | H1-03 = B1 | **Customer Safeties**: open = coast stop (whatever b1-03), alarm `SAFE`; restarts when closed and the run command is still on |
| S4 | H1-04 = B2 | **BAS Interlock**: open with a run command = baseblock, alarm `inTLK` |
| S5 | H1-05 = AF | **Emergency Override Forward Run**: runs at S6-01 (S6-02 = 0) ignoring the run command, HOA mode and the BAS interlock; Customer Safeties still stop it *(A)* |
| S6, S7 | 4, 6 | Multi-step speed / jog (not simulated) |
| A1 | H3-01 = 0 | 0-10 V frequency reference, H3-03 gain / H3-04 bias in % of E1-04 |
| A2 | H3-09 = 2, H3-10 = 0 | 4-20 mA frequency bias, added to A1 (below 4 mA reads 0) |
| MA / MB / MC | — | Fault relay: MA N.O. closes on fault, MB N.C. opens on fault |
| M1-M2 | H2-01 = 0 | During Run |
| M3-M4 | H2-02 = 1 | Zero Speed |
| M5-M6 | H2-03 = B2 | **BAS Interlock Relay Contact**: closes on a run command, opening the damper; the damper end switch closes S4 |
| FM / AM | H4-01 = 102 / H4-04 = 103 | Output frequency / output current, 0-10 V |

**Other functions any S terminal can be set to:**
- 14 Fault Reset
- 6A Drive Enable (`dnE`): the run command must be cycled after the input closes
- 70 Drive Enable 2 (`dnE`): runs again as soon as the input closes
- 20-2F External Fault `EFn`: N.O. / N.C., always / during run, ramp / coast / fast stop / alarm only, per the manual's table

**Relay settings:** 0, 1, 2 (Speed Agree, L4-02 = 2 Hz *(A)*), 6, E, 10, 38
and B2, plus the 1xx inverse settings.

## Behaviour

**HOA keypad**
- Keys: HAND / OFF / AUTO / RESET.
- S5-04 = 1: powers up in AUTO.
- HAND reference per S5-01: keypad (default), terminals, or S5-05.

**Run and reference in AUTO**
- b1-02 run command: 1 terminals (default) / 2 serial (BACnet BV1).
- b1-01 reference: 1 terminals (default) / 2 serial (BACnet AV2, Hz) / 0 keypad.

**Ramps and stopping**
- C1-01 / C1-02: 30 s, from 0 to E1-04 (60 Hz).
- d2-02 lower limit and d2-01 upper limit, in % of E1-04.
- b1-03 stopping method: **coast (default)** or ramp.

**Fault reset**
- From the RESET key, an input set to 14, or BACnet BV4.
- **Ignored while a run command is present**, as the manual says.

**Serial communication loss (CE)**
- With b1-01 or b1-02 = 2, nothing heard for H5-09 (2.0 s) gives `CE`.
- H5-04 = **3 (default) makes it an alarm only, and the drive keeps running**.
- 0 / 1 / 2 make it a fault with ramp / coast / fast stop.
- 4 runs at d1-04.
- Compare the ACH580: there, 58.14 defaults to a fault after 30 s.

**Power loss**
- L2-01 = 2 (default): a dip under about 2 s rides through with speed search *(A)*.
- A longer outage reboots the drive in AUTO. It starts again if the run command
  is present and b1-17 = 1 (the table default).
- With b1-17 = 0, the run command must be cycled.
- With L2-01 = 0, an outage while running gives `Uv1`.

**Protection**

| Code | Condition |
|---|---|
| Stall prevention | L3-02 = 120 % of drive rated current (accel) |
| L3-04 = 1 | Extends a fast decel. With L3-04 = 0 a high-inertia fan trips `ov` |
| `oL1` | Motor overload, about 150 % for 60 s, e.g. a seized fan |
| `oL2` | Drive overload *(A: same curve on drive rated current)* |
| `oH` | Alarm at L8-02 (95 °C *(A)*) |
| `oH1` | Fault 15 °C above L8-02 *(A)* |

**Instructor faults**

| Fault | Code |
|---|---|
| Overcurrent | `oC` |
| Earth leakage | `GF` |
| Output phase loss | `LF` |
| Input phase loss | `PF` |
| Low supply | `Uv1` |
| Cooling fan failed | `FAn` alarm, then `oH` / `oH1` under load |
| A1 speed wire broken | — |

Faults are user manual table 5.5 and alarms table 5.6.

## BACnet objects (`vfd_z1000_bacnet.yaml`)

From Programming Manual tables B.5-B.10.

**Commandable:**

| Object | Name |
|---|---|
| BV1 | RUN FWD |
| BV3 | EXT FAULT |
| BV4 | FAULT RESET |
| BV7-BV11 | MF Input 3-7 Cmd (virtual S3-S7) |
| AV2 | Frequency Command (Hz) |
| AV27 / AV28 | Accel / Decel Time |

**Read only:**

| Object | Name |
|---|---|
| AV9 | Frequency Reference |
| AV10 | Output Frequency |
| AV11 | Output Voltage |
| AV12 | Output Current |
| AV13 | Output Power (W) |
| AV14 | Torque Reference |
| AV18 | DC Bus Voltage |
| AI1 / AI2 / AI9 | Analog input levels, rated current |
| BI1-BI7 | Input terminals |
| BI8 / BI9 | MF outputs |
| BV13-BV16 | Run, Rev, Ready, Fault |
| BV18-BV31 | Fault bits |
| BV33 / BV35 / BV41 | Operating, Freq Agree, Base Block |
| BV42 / BV43 | Reference / run from COM |
| BV57 | Drive Comm Error |

On a real site the drive is BACnet MS/TP on R+/R-/S+/S-. The simulator presents
it as BACnet/IP on the virtual network.

**Demo mode:** writes BV1 and AV2 every second, faster than H5-09.

## Not simulated

- PI controllers (b5, S3)
- sequence timers (S2)
- the Z1000 Bypass package
- multi-step speeds and jog
- reverse run
- auto-tuning
- Modbus RTU / N2 / P1 protocols
- parameter access through AV29 / AV30
- BV5 / BV6 COM NET / COM CNTRL: shown only; the run and reference sources
  follow b1-01 / b1-02 *(A)*
